# ADR 0007 — M2 本機 Hub、持久部署意圖與受限 transport

- 狀態：已採納；實測結果另記錄於 M2 validation。

M2 的最小切片是 loopback 上單一開發管理員／demo 租戶／local-kind 叢集，由 Go 模板 UI 和 REST 提交部署。namespace 沿用 M1 的 hf-demo，建立租戶的 API 在本階段回 403；不擴展 Operator 的 watch 範圍，也不宣稱多租戶安全隔離。M4 再開放受控租戶建立與 OIDC。此決策保留 Tenant／Cluster 實體、每筆 Application 的 tenant_id／cluster_id，以及 server-side tenant ownership 檢查。

Hub 分為 domain、repository、service、Kubernetes transport 與 HTTP/UI。transport 只接受已驗證的 Application 快照與固定刪除操作，不接受 YAML、shell、exec 或上傳 kubeconfig。M3 在同一介面改用 Worker 主動建立的 mTLS gRPC 通道；M2 不產生 Agent 空骨架。

SQLite 使用 database/sql 和純 Go modernc.org/sqlite **v1.60.1**；官方該版本 go.mod 要求 Go 1.26.0、modernc.org/libc **v1.77.1**、x/sys **v0.48.0**，相容於現有 Go 1.27.2。Go 最小版本選擇後 x/sync 為 **v0.23.0**。go.mod／go.sum 固定實際相依並經 go mod verify。WAL、foreign_keys=1、busy_timeout=5000、synchronous=FULL；啟動時明確核對 WAL。共用 Store 依序執行 001～005 migration，以交易保留既有資料，目前 user_version=5；比程式支援版本更新的 schema 拒絕啟動。各入口仍依模式選擇功能，schema 版本不代表已啟用 OIDC 或 telemetry。單一連線序列化本機寫入，CAS desired revision 與 partial unique index 保護同 App 單一活動操作；Linux flock 保證一個資料庫只有一個 Hub，SIGKILL 後由核心釋放鎖。本階段不支援 HA／Windows 原生執行。

必須使用同主機本機檔案系統存 SQLite，不使用網路共享；WSL 原生 ext4 優先。預設 .local/hub 位於 checkout；可用 HF_HUB_DATABASE 選擇自己的持久本機路徑。M2 驗收測試 Hub 程序重啟／SIGKILL 恢復，不宣稱主機斷電、WSL 重啟、Docker node 重啟或備份還原已驗證。kind 沿用拋棄式 RAM etcd；業務資料存 Hub SQLite，不能存進該 etcd。

Release 快照、Operation、Idempotency 與 desired revision 在同一 SQL transaction 提交，Kubernetes side effect 位於交易之外。已提交的 QUEUED／DISPATCHED／RUNNING 操作由背景輪詢重試；command_id 與 deadline 不因重啟重新生成。CR 綁定 Hub Application ID label 和 Kubernetes UID，已有 UID 不消失重建，不接管外來 CR；同 revision 必須有相同快照，重放不更新 CR generation。API 不等待 Pod rollout。每個 App 最多一個進行中操作；最多 30 個 live App、輪詢每批 30 筆，不無限制開 goroutine。

desired／applied／last successful 各自表達接受意圖、確認 CR 寫入、完成真實 rollout。成功需驗證 CR 規格、observedGeneration／observedRevision／image／Ready，以及 Deployment 完整 managed spec、generation、副本數和 Service ownership／selector／port。Hub 與 Operator 共用 desired Deployment projection；Hub 仍直接讀真實資源 independently 確認。失敗或超時保留 Operation／Release 終態；晚到 Ready 記 LATE_READY 事件和目前可用性，沒有重新標成功或變動 last_successful_revision。再次確認使用新的操作與 revision。回滾只複製曾 ACTIVE／SUPERSEDED 的快照，來源不修改。刪除使用 UID precondition，等待 CR、Deployment、Service、ReplicaSet 和 Pod GC，SQLite 不硬刪。

本機 bootstrap 保留 kind 管理員 kubeconfig 供安裝 CRD／Operator／RBAC。Go bootstrap-hub 透過 TokenRequest 產生約 8 小時的 namespace ServiceAccount kubeconfig，私密檔案留在 .local；Hub 只讀這份受限憑證。Hub 拒絕管理員 client certificate、exec/auth plugin、impersonation、外部 endpoint 和 proxy；首次連線用 SelfSubjectAccessReview 確認 Application create 可用、Secrets／exec／跨 namespace 寫入受拒絕，不只信任 kubeconfig 名稱。Role 只允許 hf-demo 的 Application CRUD，以及 Deployment／ReplicaSet／Service／Pod 讀取。沒有 Secrets、exec、workload 寫入、namespace 建立或跨 namespace 操作。token 到期後重新 make hub-bootstrap 並重啟 Hub；M3 多叢集模式採 Agent 通道，M2 仍保留受限本機 transport。

若 create 已到達 Kubernetes、但 UID acknowledgement 尚未持久化就失敗，DELETE 先從 Hub ID label 相符的 CR 恢復 UID，將 UID 與事件交易保存後才刪 CR。此 binding 不宣稱 revision 已成功套用；之後仍用 UID 等待真實 GC。CR 已不存在且 UID 未知時，也保守等待同應用名稱的殘留 ReplicaSet／Pod 清除。

背景觀測在 desired／applied 尚未一致時仍持續執行。確認 ownership、UID 與完整 CR spec 後可交易恢復 applied acknowledgement；逾時操作只觀測，不再次寫入 CR，也不改寫 Release／Operation 終態。002_observations.sql 在交易中保留履歷並加入目前觀測錯誤欄位；完整 schema 與模式說明見 [Hub 導讀](../../stages/m2/hub/README.md)。生命週期事件仍以 operation／kind 去重；OBSERVED_DEGRADED／OBSERVED_RECOVERED 允許多次轉換，但同一原因不因輪詢重複插入。UI／API 直接顯示持久化原因，與歷史操作結果分開。

DEV_AUTH_MODE 是 M2 固定模式，HTTP 只能顯式綁定 127.0.0.1；Host allowlist 防 DNS rebinding，mutation 拒絕跨 Origin／Sec-Fetch-Site，JSON API 要求 application/json，UI 使用 HttpOnly／SameSite=Strict cookie 與 CSRF hidden field。UI 無 JavaScript，活動操作用 meta refresh；終態停止刷新，避免清空使用者填寫的表單。此保護不等於 OIDC、多租戶授權或正式遠端部署安全。

資源 defaults／maxima 位於 stages/m2/policy.json，預檢包括 replicas+1 的 surge requests。這是每應用開發上限，不能當作 namespace Admission 的替代。kind E2E 額外建立測試 ResourceQuota，確認 surge Pod 受拒絕時 Operation 報 FailedCreate，然後移除測試 quota 並用新 revision 恢復。
